# Prompt Template 04 — Theme Validation

## Input
Any component or section — typically a champion from Sprint 1 or Sprint 2

## Output
Light and Dark variants with:
- Identical geometry
- Identical hierarchy
- Identical interaction
- Identical content

## Constraints
- Semantic variables only — bind to OLUK / Semantic / Closeout G1 (518:817)
- Light mode: mode 518:1
- Dark mode: mode 518:2
- No structural divergence between themes
- No hardcoded colors — every fill must trace to a semantic variable
- Surface rhythm preserved: Canvas → Surface → Raised → Evidence

## Validation
- Side-by-side comparison at identical viewport
- Contrast outcomes documented per surface
- Any structural difference between themes is a defect

## Deliverables
- Paired Light/Dark specimens
- Contrast outcome report
- Variable binding inventory
- MAKE_RESULT receipt

## Return Path
Validated pair → Runtime Studio → ReviewOS → Codex
