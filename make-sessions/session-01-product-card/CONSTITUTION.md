# Olympus Labs UK — Figma Make Creative Frontier Constitution

**Status:** Current Make brief
**Date:** 2026-08-04
**Controlling plan alias:** `ids-plan.md`

## Mission

Use the resolved Final-Design work as a directional baseline and source of proven relationships, then use Figma Make to design a more complete, adaptive and visually authored light-mode commerce experience.

The first Make pass must not reconstruct Figma Design nodes or turn authority boards into SSR replicas. It begins from selected PNG references so Make reads the material, spatial and compositional direction without spending the run converting native layers. After a visual direction wins, introduce selected Figma components, nodes and variables to rationalize and extend that direction.

The Make lane therefore works in this order:

> **sealed PNG-led creative frontier → cross-context relationship transfer → adaptive card champion → selective native integration → customer-facing routes → responsive convergence → Make Design Gate → system consolidation → runtime translation**

## What the Final-Design work provides

Final-Design is not a page template that Make must trace. It provides:

* proven product truth and content hierarchy;
* the current Native Light material direction;
* canvas, raised-surface and media-chamber relationships;
* reusable semantic structures such as ProductMetricRail, PurchaseRail, Dossier, LabReports, Lab Verification and TrustEvidenceSpine;
* reference typography, color and density behavior;
* examples of what already failed.

Make may improve the silhouette, material expression, spatial rhythm, adaptive behavior and interaction of these structures. It must retain their semantic jobs and canonical product truth.

## Initial Make method

### Pass 1 — Creative design from images

* Attach a small set of strong PNG references rather than entire Figma files.
* Generate three genuinely different high-fidelity treatments for one narrow problem.
* Judge design quality, not code structure or Make self-evaluation.
* Do not import native nodes during the first exploration.
* Use approved product renders in the visual output; do not use empty linework chambers.

#### Sealed MF-01A input manifest

The opening ProductCommerceCard run uses exactly three PNGs from the sealed manifest:

1. `productcommercecard-productgrid.png` — vertical ProductGrid/featured relationship;
2. `horizontal-product-card.png` — horizontal related/upsell relationship;
3. `MF01-C-compact-raised-white-purchase-panel-v2.png` — compact rail/QuickAdd relationship.

No fourth asset, separate render, G0 reference, native node, system board or legacy Make export may enter MF-01A. The sealed packet is deliberately sufficient for Make to design a family without converting Figma Design work or averaging incompatible sources.

### Pass 2 — Select relationships and transfer them

* Select the strongest relationships across the candidates rather than accepting one entire output uncritically.
* End MF-01A after relationship selection; do not synthesize a champion in the same run.
* In MF-01B, test the selected relationships against one homepage entry, the PDP Section 1 exception, one connected embedded-divider composition and one genuine canvas-separated composition.
* Reserve the curated G0 reference and route/evidence reference PNGs for MF-01B.
* Keep MF-01B PNG-led. Native nodes still do not enter.

### Pass 3 — Adaptive champion and native integration

* In MF-02, synthesize one ProductCommerceCard family only after the relationship transfer survives.
* Introduce only the relevant Figma components, nodes and variables.
* Preserve ProductMetricRail, governed identity fields and exact product truth as reusable structures.
* Reconcile the selected Make design with the native semantic API without flattening the creative result back into a reference board.

### Pass 4 — Adaptive system

* Build responsive component families and route compositions.
* Add local interactive behavior, responsive reflow and state transitions.
* Keep prototype code local to Make until the Make Design Gate passes.

## Current light-mode direction

Native Light is the starting design concept, not a finished template:

* cool luminous canvas;
* raised white commerce and information planes;
* bounded linear or full-field white-to-ice media chambers;
* cobalt concentrated in product packaging, primary action, links, icons and metrics; the sealed MF-01A card family has no cobalt outer outline or decorative top-edge eyebrow;
* blue-shifted neutrals rather than achromatic default greys;
* visible canvas used as margin and separation;
* content-driven silhouettes rather than a universal rectangle.

Make should strengthen this direction through more authored card shapes, better chamber-to-content transitions, more confident typography, responsive composition and interaction. It may not revert to cream, blanket grey, broad inverse bands, technical-OS decoration or generic card stacking.

## ProductCommerceCard contract

The first Make frontier is the adaptive ProductCommerceCard family.

Every context preserves this semantic order:

> **Media chamber → ProductIdentityStack → ProductMetricRail → quantity or inventory + price → actions**

Required contexts:

* Product Grid;
* Featured Product;
* Quick Add vertical;
* Quick Add horizontal;
* related/upsell rail;
* compact/mobile rail.

Make may change:

* silhouette and corner strategy;
* chamber proportion and transition into the content plane;
* elevation and grounding;
* internal rhythm and information density;
* action placement by context;
* responsive reflow;
* hover, focus, selected and added states.

Make retains:

* actual approved product render;
* product identity hierarchy;
* ProductMetricRail's quantified-truth role;
* whole-pound price formatting;
* context-specific commerce state: quantity stepper in the vertical and horizontal seeds; text-only inventory in the compact seed; no mandatory inventory icon;
* colorless qualitative/support chips versus cobalt quantified metrics;
* no crossed price and no per-serving price.

For MF-01A specifically:

* vertical ProductGrid and Featured forms use a transparent embedded divider to connect the bounded chamber and raised white purchase plane;
* the horizontal form uses a connected sculpted seam and no cobalt top-edge eyebrow;
* the compact form keeps a white elevated purchase panel under its bounded chamber;
* the page canvas surrounds the card family but does not become an internal gap between chamber and purchase content;
* partial neighboring cards in the compact PNG communicate rail context only and do not define the component boundary.

## Typography and color

* Plus Jakarta Sans leads display/editorial hierarchy.
* Inter supports interface, commerce and technical content.
* Purchase and ProductCommerceCard UI uses Inter.
* Barlow Condensed, Archivo, Cousine and Inter Variable are rejected.
* Core identity/metric cobalt: `#0057FF`.
* Interactive cobalt: `#256DFF`.
* Current blue-shifted support references: `#F8FAFC`, `#D9DEE8`, `#667085`, `#101114`.
* Make may tune material recipes and optical relationships during exploration, but it may not create a disconnected palette or silently rename the semantic roles.

## Make outputs

Each run produces:

* high-fidelity customer-facing design, not a system-board specimen;
* three credible variants during the frontier pass;
* a relationship-selection record and a short rejection summary in MF-01A;
* a cross-context transfer record in MF-01B;
* the selected champion only from MF-02 onward;
* desktop proof first, followed by 768 and 390 adaptation from MF-02 onward;
* local interaction proof where relevant;
* a list of native components/variables to introduce in the next pass;
* no runtime integration claim.

## Runtime boundary

Figma Make may implement local state, responsive behavior and route transitions to prove the experience. It does not decide the production basket adapter, inventory source, quantity cap, payment endpoint, analytics contract or server ownership.

Runtime translation begins only after the Make Design Gate approves the cross-route champion and the design system is consolidated from that result.
