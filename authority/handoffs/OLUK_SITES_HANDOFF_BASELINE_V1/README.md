## Purpose

This baseline resolves the ownership error in the earlier Shopper-only
foundation experiment. Codex Sites is the source of visual composition,
responsive anatomy, canonical primitive contracts and customer typography.
Shopper is a consumer of this handoff and must preserve its own SSR,
same-origin bridge and runtime-boundary responsibilities.

The baseline deliberately serializes the sources that differ in maturity:

| Input | What it contributes | What it does not authorize |
|---|---|---|
| Sites composition commit `4d697e1` | real shell, page composition, primitive use, responsive behavior | deployment or runtime mutation |
| Published commit `b0227a1` | exact 128-role light token declaration set | automatic component/route adoption |
| `SITE-ROUTE-LEDGER.json` | 73 canonical structural patterns | a live runtime router or visual-completion claim |
| Current route data | 52 executable candidate destinations | replacement of the 73-pattern ledger |
| C2/Woo/Initiator contracts | data, availability, commerce and payment ownership | CSS/component ownership |

## Consumer rules

1. Copy or compile the token declaration set only from the hash-locked source.
2. Port the named primitive and family contracts before composing a customer
   route. Do not invent a local role, card anatomy or route module.
3. Keep stock, success, evidence, unavailable, pending, error and disabled as
   distinct state semantics.
4. Treat all proof listed here as candidate evidence. It cannot establish
   production, deployment, customer-route adoption, or dark-mode release.
5. Keep Woo and C2 fact ownership and Initiator's payment-terminal boundary
   unchanged.
