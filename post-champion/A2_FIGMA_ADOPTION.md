# A2 — Native Figma Adoption

## Load gate

Do not load or execute this file until the human review gate records a locked
Light Identity Authority V1.

The accepted Make result is visual evidence. It is not automatically a native,
production-grade Figma library.

## Objective

Reconstruct and normalize the accepted light system in the existing R6 Design
file using native, reusable Figma structures while preserving the verified
visual result.

## Required authority page

Create:

`LIGHT IDENTITY AUTHORITY — NATIVE V1`

Keep the accepted Make proof and localhost capture beside the native
reconstruction. Label all three lanes:

- Make visual candidate;
- exact raster capture;
- native editable authority.

## Native systemization

After measuring the accepted result, finalize:

- semantic color and surface variables;
- typography styles and responsive type roles;
- spacing and sizing variables;
- radius, rule and functional-elevation roles;
- media chamber roles and render-slot behavior;
- Auto Layout direction, wrapping and resizing;
- component properties and nested primitives;
- variants and visual state sets;
- responsive constraints;
- interactive prototype states where useful;
- accessibility and reduced-motion annotations;
- export and naming conventions.

Do not promote specimen dimensions such as `1171px` into universal tokens
without validating them in the accepted pages.

## Component families

At minimum normalize:

- GlobalShell / UtilityRail / PrimaryNav / ContextRail / MegaMenu / MobileMenu;
- Hero / FlagshipHero / OpenLabHero / ReportHero;
- CategoryFamilyRail / CategoryCard;
- ProductCard Grid / Rail / Featured / QuickAdd / Related / CartRow;
- MediaChamber Hero / PDP / Card / Thumbnail / Compare / Cart;
- PDP Gallery / ProductIdentity / MetricRail / PurchasePanel / AssuranceRail /
  DescriptionDossier;
- EvidenceThreshold / EvidenceLedger / ReportRow / SourceDrawer /
  StatusGuardrail / WarningSurface;
- Collection filters, sort, comparison and state surfaces;
- CartDrawer / Bag / CheckoutBlock / TrackingTimeline;
- Newsletter / CTA Band / Footer variants;
- shared glyph and control families.

## Component API board

For each family record:

- component and instance name;
- purpose;
- shared subcomponents;
- visual variants;
- content properties;
- state properties;
- theme boundary (Light V1 only);
- responsive behavior;
- required governed data;
- accessibility label/role intent;
- export or implementation mapping.

## Adoption checks

- No accepted page relies on detached one-off copies where a shared family
  exists.
- Visual fidelity is checked beside the exact raster reference.
- Product renders remain linked to product/role, not baked into shell tokens.
- Evidence, transaction, decision and media surface roles remain distinct.
- Variables describe the accepted design; they do not force the design to match
  premature token guesses.
- Dark mode remains a separate future translation after the light system is
  stable.
